# benchsweep

Go のベンチマークを、**バージョンを横断して同じ制約の下で**回すツール。

数字を公開する前に「その差はコードの差か、Go の差か、測定環境の差か」を切り分けるために使う。

必要なのは `docker` と `python3` だけ。Go をローカルに入れる必要はない。

## 使い方

```bash
git clone https://github.com/makoto-developer/benchsweep
cd benchsweep
./run.sh <ベンチ対象のモジュールディレクトリ> [ベンチ正規表現] [count]

# 例
./run.sh ~/src/category-theory-go . 3
./run.sh ~/src/category-theory-go 'SeqStyles' 6
```

`results/` に生の出力が残り、最後に Markdown の比較表が出る。表はそのまま記事や `BENCHMARKS.md` に貼れる。

## 何を固定しているか

| 制約 | 既定値 | 環境変数 | なぜ |
|---|---|---|---|
| CPU 数 | 4 | `BENCH_CPUS` | 割り当てが変わると並列度が変わる |
| cpuset | `0-3` | `BENCH_CPUSET` | 走るコアを固定する。他コアへ移ると分散が増える |
| メモリ | 4g | `BENCH_MEM` | GC の頻度が変わる |
| `GOMAXPROCS` | 4 | `BENCH_GOMAXPROCS` | **下記の理由で必須** |
| ネットワーク | `none` | `BENCH_NETWORK` | 測定中の外部通信を断つ |
| ソース | read-only マウント | — | ベンチが対象リポジトリを書き換えないことを保証する |

対象バージョンは `BENCH_SERVICES` で絞れる。

```bash
BENCH_SERVICES="go1.25 golatest" ./run.sh ~/src/category-theory-go
```

### `GOMAXPROCS` を明示している理由

**Go 1.25 から、ランタイムが cgroup の CPU 帯域制限を見て `GOMAXPROCS` を決める。**
コンテナに `cpus: 4` を掛けると、1.23 / 1.24 はホスト（macOS なら Docker の Linux VM）の
全 CPU 数を見るのに、1.25 以降は 4 を見る。固定しないと**バージョン差だと思ったものが
並列度の差**になる。ここを踏むと結論がまるごと反転しうる。

## サービスは順番に走る

`run.sh` は `docker compose run` を1サービスずつ呼ぶ。`docker compose up` のように
並列起動すると、コンテナ同士が CPU を奪い合って測定が混ざる。
**隔離とは「同時に走らせないこと」も含む。**

## 読み方 —— ns/op より allocs/op を見る

`compare.py` は2つの表を出す。

- **ns/op**: 環境で動く。macOS の Docker は Linux VM 越しなので、ホスト実行より遅く、分散も大きい。
  **バージョン間の小さい差（数十%以内）をここから読み取ってはいけない**
- **allocs/op**: 決定的。CPU にもスケジューラにも VM にも依存しない。
  **ここが動いていれば、それは本物のバージョン差**（アロケーション戦略が変わった、インライン化が変わった等）

最後に、アロケーション数がバージョン間で 1% を超えてずれたベンチを一覧で出す。
ずれていなければ「ns/op の差は環境由来」と言い切ってよい。

漸近的な差（$O(n^2)$ か $O(n)$ か）を主張したいときも allocs/op を主軸にする。
$n$ を振ってアロケーション数が二次で増えることを見せるほうが、時間より強い証拠になる。

## 制限

- 計測するコンテナは `network_mode: none`。依存は先頭の `warm` サービス（ここだけネットワークを
  開ける）が共有ボリュームへ落とすので、`rapid` などに依存するモジュールでもそのまま動く。
  キャッシュは run 間で残る（2回目以降の `warm` は一瞬で終わる）
- ベンチのハーネスは全バージョンで同一にすること。`b.Loop()` は **Go 1.24 以降**にしかないので、
  1.23 を含めるなら `for i := 0; i < b.N; i++` に揃える
- macOS では Docker が Linux VM 上で動くため、**絶対値はホスト実行と一致しない**。
  このツールが保証するのは「バージョン間で条件が揃っていること」であって、
  「ホストと同じ数字が出ること」ではない
- 未リリースのバージョン（イメージが無い）は自動でスキップされる
- **測定中はホストで他の作業をしない。** macOS では対象コンテナもホストの作業も同じマシンを使う。
  実際に、sweep 中にファイル書き込みを走らせたら、そのランだけ全ベンチ一律に約1.6倍遅くなった
  （`allocs/op` が全バージョン一致していたので誤読を免れた）

## 実際に使った例

「Cayley 表現は Go でいつ効くのか」の測定で、Go 1.23.12 / 1.24.13 / 1.25.13 / 1.26.5 / 1.26.6 の
5バージョンを回した。**30本すべてのベンチで `allocs/op` が一致**し、`ns/op` は 1.23 比で
0.48〜2.09 倍にばらけて傾向が無かった。結論は「この題材に Go のバージョン差は無い」。

`ns/op` だけを見ていれば「1.25 で退行した」と誤読していた。
